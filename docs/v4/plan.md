# V4 Plan — 镜头序列实施计划

状态: 规划中（T1 未开始）
日期: 2026-08-16

## Grill 决策记录

1. **核心模型**：把「多相机并行」升级为「镜头段序列」（镜头按时间顺序组织）
2. **段模型**：相机对象（上层实体）+ 镜头段（下层，引用相机，多对一）
3. **机位复用**：一个相机对象可被多个镜头段引用
4. **序列 vs 并行**：靠「时间范围是否重叠」判断（不重叠=序列，重叠=并行）
5. **多轨道是底层**：单时间轴是「段不重叠」时的特例
6. **S/C 判据**：去重后的关键帧 pose 数 ≤2 = S（可编辑），>2 = C（自由）
7. **S/C 准确表述**：S = 能用「2 pose + LINEAR/CUBICSPLINE」无损表达；C = 做不到的（多关键帧 / Back·Bounce·Elastic / 约束 / 复杂贝塞尔），导出后必然 3+ pose
8. **段边界** = 独立 Action + NLA track 的边界（blend 显式存储）
9. **每段一个独立 NLA track**（一个 track 只放一个 strip，禁止多 strip——实测会导出 0 动画）
10. **glTF 丢失绝对时间**：strip 的 frame_start 偏移不导出 → 段的绝对起止时间靠 sidecar 补救
11. **起幅落幅停留** = 重复关键帧（不增 pose 数）；**缓动** = 切线（CUBICSPLINE，不增 pose 数）
12. **UI 一级段列表**（非两级相机→段，因段自带相机名 + 时间）
13. **自动序列播放**（本期做，体现"序列"本质）
14. **旧并行 blend 本期做**（走多轨道，保留并行语义）
15. **轨道对用户不可见**，用户只看到「相机对象 → 段」两层
16. **编辑 + 导出** → V5（本期不做）

## 实施计划（4 切片）

依赖图：

```
T1（单段识别地基）
├─ T2（多段序列 + 自动播放）── T4（skill 强约束改造）
└─ T3（并行兼容多轨道）
```

1. **T1**：sidecar + 单段识别 + 段列表 + S/C（无依赖）
2. **T2**：多段序列 + 自动播放（依赖 T1）
3. **T3**：并行兼容多轨道（依赖 T1）
4. **T4**：skill 强约束改造（依赖 T2，验证多段生成）

## 关键风险

- **AI 是否遵守「每段一个 Action + NLA track」**：现有 AI 生成完全没用 NLA（实测），需 T4 强约束 + 手动验证
- **glTF 绝对时间丢失**：已用 sidecar 解决（Blender 脚本导出时读 NLA strips 写 segments.json）
- **Blender 脚本读 NLA 的测试**：无法单元测试（需 Blender 环境），靠手动生成验证
